# The Python control plane

`qwen-apu` becomes a shell-free Python control plane around native inference
engines. llama.cpp with its Vulkan backend, the patch series and its GLSL
kernels, stable-diffusion.cpp, the small native Vulkan probes, the static
WebUI, and the declarative TOML, JSON, and evidence files remain the product;
installation, configuration, supervision, deployment, model management, tool
authorization, health, evidence, benchmarking orchestration, and CI helpers
move into `src/qwen_apu/`.

## Boundary

One user-owned application prefix, the runtime root `remote/qwen-home.sh` and
`qwen_apu.runtime.paths` both declare, holds every generated byte:

```text
.runtime/
  venv/          the qwen-apu Python environment (dependency isolation only)
  bin/ opt/ models/ deployments/ state/ artifacts/ cache/ tmp/ logs/ results/
```

The no-sudo contract: install, update, launch, stop, and ordinary use require
no sudo and write only under the declared runtime root. `bootstrap.py` is the
zero-dependency entry point; `python3 bootstrap.py` under `strace -f` writes
under the root alone, with pip's scratch directed there through TMPDIR.
Privileged research controls (RyzenAdj, forced clocks, KSM, package changes)
leave the application and take a separate `research_admin` surface the server
never imports.

## Phase 1: package, paths, registries, ratchet

| Component | Python authority | Shell authority it matches | Parity test |
| --- | --- | --- | --- |
| Runtime root names | `qwen_apu.runtime.paths` | `remote/qwen-home.sh paths` | `tests/test_runtime_paths.py` |
| Layout and marker | `RuntimePaths.lay_out` | `remote/runtime-root.sh init` | same |
| Registries | `qwen_apu.config.models` | `remote/model-registry.sh` | `tests/test_config_registry.py` |
| Patch series | `load_patch_series` | `remote/llama-patch-series.tsv` | same |
| Deployment read | `qwen_apu.runtime.deployment` | `resolve-active-deployment.sh`, `verify-deployment-bundle.sh` | `tests/test_runtime_deployment.py` |
| Ratchet and CI | `qwen_apu.ci` | `.github/workflows/python-control-plane.yml` | `tests/test_ci_ratchet.py` |

The layout gains `venv`, `artifacts`, and `logs` on both authorities in one
change, so `make verify-layout` and `qwen-apu status` read one set.

The ratchet freezes the tracked shell set in `config/shell-baseline.txt` and
refuses growth, `shell=True`, string subprocess commands, `sudo` under
`src/qwen_apu/`, and owned paths outside the root. `python -m qwen_apu.ci`
runs the ratchet, ruff, mypy, and pytest as one hosted job.

## Order of the remaining phases

2. Downloads and native artifacts: model digests, source acquisition, patch
   application, the prebuilt Raven2 bundle, `config/native-builds.toml`.
3. Deployment manager: build, activate, rollback under `fcntl` locks with
   `os.replace`.
4. Supervisor: foreground by default, `--daemon` through `start_new_session`,
   `state/control.sock`, pidfd ownership, tmux removed.
5. Gateway: one origin over the broker, web MCP, artifact, and image services.
6. Conversations in SQLite with a Temporary mode.
7. Documents, calculator, file search, artifact export.
8. WebUI split into ES modules.
9. Shadow deployment on alternate loopback ports.
10. Cutover, shell deletion in batches, Makefile removal last.
