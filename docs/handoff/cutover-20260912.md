# Cutover receipt: the Python appliance serves production

On 2026-09-12 the laptop's production address moved from the shell launch
chain to `qwen-apu appliance serve`, run from the canonical checkout at
`main` with the production runtime root, and stayed there. The sequence, in
the order the operator directed and the rehearsals proved:

1. The canonical checkout was brought to `main`; its synced `remote/`
   overlay is retained in `git stash` under
   `synced-overlay-before-cutover-<utc>`.
2. `bootstrap.py` laid out the venv in the production root, and
   `deployment build python-prod` sealed a bundle from the active legacy
   bundle's server, ledgers, router preset, and Q4_K policy;
   `deployment activate python-prod` made it current with the legacy bundle
   as `previous`.
3. Legacy was verified `state=running`, then torn down through
   `qwen-teardown.sh` with no residue.
4. The appliance started detached (`setsid nohup nice -n 19 ... appliance
   serve --router --port 8080 --gateway-port 42069 --bind-host 10.0.0.170
   --image-profile image-sdxs-512-a --web-profile web-open --file-root
   <tree>/docs`), pairing ran once through the printed code, and the
   acceptance driver ran against `http://10.0.0.170:42069`.
5. After `main` gained the lane children, the appliance restarted in place
   and the acceptance ran again with `--previous-report`, proving the saved
   conversation from the first run.
6. A final restart minted the pairing code the operator uses; the service
   keeps running with no window wrapper, no tmux, no unit file.

A skipped item names the route or the argument its claim needs; a 404 from a route this branch does not mount is a skip, and a 401 or 403 is a live gate answering and stays a failure.

The two skipped items are the stop-dependent proofs (the lease free after
stop, no residue after teardown), which a service meant to keep running
does not take; both passed in every cutover rehearsal, most recently
`docs/handoff/cutover-rehearsal-20260912.md`.

Recovery stays one command pair away: `qwen-apu appliance stop`, then
`remote/qwen-teardown.sh` and `remote/qwen-lan-launch.sh lan-authenticated
low-async` from the same checkout, with `deployment rollback` restoring the
legacy bundle as current where a bundle difference is wanted. The pairing
code is one-time per launch and lives at `state/gateway-pairing.secret`
until it is used.
