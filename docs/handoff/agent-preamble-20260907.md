# Raven2 successor operating boundary

`AGENTS.md` owns repository rules. The serving release stays
`lease-q4k-6b262d93-r1`; the active and previous bundle links, running executable,
standing VM, stock power policy, LAN authentication, held sweep and archive refs
remain the operator's protected surfaces. Source integration advances independently
of deployment activation. DO NOT roll back, rebuild the release for documentation,
launch more agents, pause the VM, or expand the runtime architecture.

The workstation runs one repair cluster at a time in a fresh linked worktree.
Preserve local handoff bytes before editing, review the exact diff, and stage
named paths. DO NOT use `git add -A`, stash, forced worktree removal or branch
force-deletion to resolve a checkout collision. A worktree leaves only after its
commit disposition, tracked changes, untracked and ignored contents, and process
ownership are inspected. Archive refs stay retained.

The baseline repair precedes device acquisition. Run focused fixtures and the
exact committed-head gate through `remote/run-repository-gate.sh`, using the
shared immutable cache and a fresh mutable fixture state. Record the terminal
result, tested head and reused-cell count. A historical PID or quiet log carries
zero completion authority. Confirm GitHub PR and merge state independently of
local driver output; keep a failed or interrupted gate as its actual outcome.

The device queue starts with one named 2B single-mode canary. Admission requires
a completed streamed warmup, four fixed-length repeats, actual executable,
model, Q4_K selection, placement and thread identity, accepted delivered-clock
telemetry, bounded teardown, state restoration and authenticated service health.
The registered lease profile keeps the orchestrator at nice 0, preserves KSM as
found and the standing VM, sets stock power and fixes GFX/FCLK at levels 2/2.
Serving policy assigns inference priority. Broader privileges are outside scope.

An infrastructure failure ends the window and retains its artifacts. The 0.8B
and 4B anchors advance only after the 2B canary passes, under the same registered
conditions. The thirteen-row portfolio and the full baseline campaign stay
queued. Single-binary repeatability uses single mode. A bracket requires a real,
identity-compatible candidate with a different executable digest.

Raw acquisitions live under `.runtime/results/<run-id>`. Retain source and
execution identities across the whole window; synchronize before the window and
freeze scripts and deployment links during acquisition. Reviewed sanitized
records enter tracked evidence afterward. Preserve acquisition identity separately
from the reader revision that interprets it. A parser repair reprocesses retained
records and does not automatically invalidate their acquisition.

Keep five claims separate: `within_binary_repeatability`,
`cross_binary_token_comparison`, `acquisition_completeness`,
`instrument_admission`, and `performance_result`. Four repeats in one session
measure within-session variation; C K K C supplies two launches per role and a
descriptive ratio. The ratio supplies neither a confidence interval nor promotion.
