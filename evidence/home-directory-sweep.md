# The appliance home directory, swept into the runtime root

The appliance wrote 398 entries into `$HOME` over the campaigns this tree
records: 130 measurement-output directories, 251 console and gate logs, and one
loose analysis script. `AGENTS.md` states that every generated byte of the
appliance lives in one declared runtime root, and `make doctor` reports
predecessor paths outside it, but a campaign output directory placed directly
under `$HOME` was outside the doctor's enumeration and so accumulated
unreported. On 2026-09-06 all of it moved to
`$QWEN_HOME/results/home-sweep-20260906/`, leaving `Github` as the only
non-dotfile entry in the home directory, and `MANIFEST.tsv` beside it carries
one row per directory with its byte count and file count.

The sweep moves rather than deletes, because a measurement this tree cites is
worth more than the disk it occupies and because the classification below
distinguishes retained from unique rather than proving each byte redundant.

## What the sweep holds

A survey of every directory against the committed `evidence/` tree, matching by
SHA-256 rather than by name, reads 1.23 GiB as follows.

| class | directories | bytes |
| --- | ---: | ---: |
| retained in `evidence/` already | 73 | 428.6 MiB |
| regenerable from code and a pinned input | 4 | 775.2 MiB |
| aborted, failed, or superseded attempts | 36 | 49.2 MiB |
| unique measurement | 15 | 7.34 MiB |

The retained class matches by content rather than by digest count. The repository
sanitizes the private hostname to `qwen-laptop`, the home prefix to `$HOME`, and
MAC addresses to `<mac>` before committing, so a path-bearing file diverges in
digest while its substance is retained whole, and a large campaign deliberately
retains decisive-arm summaries and receipts rather than every raw per-dispatch
table. One stage was checked byte-for-byte to establish that reading:
`raven2-kernel-census-20260902T2011Z-2b-calibration-v10` holds 590 files, its
committed twin holds 54, and every one of those 54 is hash-identical to its
source here.

`qwen-test-models` is the largest single entry at 674.4 MiB and holds none of
this tree's checkpoints: 109 synthetic per-architecture GGUF stubs, from
`arcee-dense.gguf` to `xverse-dense.gguf`, whose digests match no
`expected_sha256` in any fetch script and no file under the root's own
`models/`. It is llama.cpp's architecture-coverage corpus. `qwen-frozen-binaries`
holds one `llama-server` byte-identical to the copy the root already carries at
`deployments/emergency-forced-tail-40f7b775/llama-server`.

## What committed evidence cites

Forty-one of these directories are named inside committed evidence files, some
heavily: 72 files each cite the four `q4k-served-ab-*` runs, 41 cite
`fixed64-scoreboard-20260901T2011Z`. A `$HOME` path in a committed record is a
sanitized historical path rather than a live pointer, which the tree already
demonstrates: `$HOME/qwen-webui-state` appears in 1307 committed files and
`make purge-legacy` removed that directory with no record broken.

The one case where a citation names bytes rather than a location is the E1
shader lab, whose receipts cite `$HOME/e1-lab-20260902/spv/e4-nsh.spv`. That
receipt carries `spirv_sha256` and `spirv_bytes` on the lines beside the path,
so the module is identified in the committed record by the same
identity-without-the-blob pattern the private hardware captures use, and the
bytes are reproducible from the pinned source and the patch series.

## The unique residue

Fifteen directories hold measurement no committed file reproduces. Two are gaps
the tree names itself:

- `qwen-representation-arm` holds the two ABBA runs behind
  `evidence/representation-gate-16-bit.md`, which states at line 114 that "the
  retained repository lacks the raw arms and a weight-level identity witness."
- `qwen-universal-sweep` holds the raw fourteen-arm sweep behind the
  seven-checkpoint comparison in
  `evidence/model-admission/universal-candidate-ladder.md`. That document's
  9.01 and 11.61 GB/s figures, and the 11.1% and 11.5% offsets AGENTS.md quotes
  from them, have no raw backing anywhere under `evidence/`.

The rest -- the six `qwen-speculation-matrix` runs, `qwen-depth-wedge`,
`qwen-priority-probe`, `qwen-kv-cache-factorial`, `qwen-dpm-force`,
`qwen-bench-repeatability`, `qwen-quality-gate`, and the E1 lab sources -- are
cases where a committed document quotes the derived numbers and the raw logs
were never copied. Each is a weaker claim than the two above, since the finding
is retained and only its transcript is not.

Promoting any of these into `evidence/` is a separate decision per directory,
and this record exists so that decision reads from a classification rather than
from a directory listing.
