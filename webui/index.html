Authorize one web search

The model proposes these exact arguments. An approval signs a grant over them and admits one search; the served path refuses any other query, domain list, publication window, cached age, or larger result count.

The model proposes these exact arguments. An approval signs a grant over them and admits one generation; the served path refuses any other prompt, negative prompt, seed, size, step count, or profile.

The llama.cpp UI is served by the ordinary router launch

llama-server serves one page at the root of one listener. This appliance runs qwen-web-launch.sh, which passes --path at the directory holding this page, and that same flag is what makes the binary's own compiled-in llama.cpp UI go unregistered. Starting the appliance through qwen-launch.sh instead leaves --path unset, and the llama.cpp UI then answers at this same address and port.

Three surfaces exist on this page alone, because each one is built here rather than in the served binary: the approved web search, the approved image generation with its artifact cards and vision review, and the feature roster this page reads beside itself. A turn run in the llama.cpp UI reaches the model and reaches none of them.
